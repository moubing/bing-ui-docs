计划日期：2026-09-11。2026-09-12 更新：八个阶段的文档实现与验证已完成，含 Cursor 在内的 34 个组件全部通过验收，文档修订 r8。站点 265 项、独立导出与阅读应用 231 项浏览器检查通过，详见[整体收尾记录](bing-ui-0.6.0-stage-8.md)。各阶段分别提交，临时文件清理仍受执行策略限制，见[升级基线](bing-ui-0.6.0-baseline.md)及阶段记录。

已确认范围：**文档站整体同步新版风格，保留现有页面结构。** 沿用现有路由、导航组织和 Markdown 文档体系，调整首页、导航、正文、API 表格、示例容器及参数面板的视觉，并分批核对组件用法。

### 阶段 1：先解决分步升级的基础问题

- 以当前安装的 0.5.3 类型及文档作为旧版基线，对照 0.6.0 的公开类型、运行时默认值、主题变量和行为，补齐逐组件差异表。
- 迁移建议在独立分支推进，依赖先精确锁定到 `0.6.0`，由 pnpm 更新锁文件。
- 为逐组件记录保留“API/正文、网页预览、独立示例、AI 导出、验证”五项状态，完成后再勾选。
- 先处理影响所有页面的共用问题，例如复制按钮的中文定位器；升级后的其他类型错误和失效断言登记到对应组件，逐批处理。
- 明确区分“目标包版本”和“已验证组件”。建议在现有注册表/导出清单上增加最小的迁移状态，保留安装版本校验，逐组件记录是否已验证 0.6.0。
- 迁移中的页面及 AI 文件应明确标注待验证；不能把全局版本改为 0.6.0 后仍对所有组件输出“仅验证该版本”。全局版本或生成头部变化时先整体重新导出，后续恢复按组件同步。
- 新版 AI 入口只将已验收组件列为已验证覆盖，其余列为迁移中。全部完成后统一收口，无须在本轮引入完整多版本文档系统。

### 阶段 2：先形成可复用的页面标准

公共视觉重点处理 `app/assets/css/main.css`、Header、文档布局、提示块、API 表格和示例容器：

- 统一浅色、深色、system 主题的背景、文字、边框、强调色、阴影和间距；优先映射组件库语义变量。
- 校准正文与标题字重、代码字号、参数面板密度，让新版紧凑控件在文档中保持清晰可读。
- 检查直接作用于组件内部的旧样式，尤其 Dialog 遮罩和转场容器；已不需要的补丁移除，其余优先使用公开属性或变量。
- 让常规示例使用中性背景；磨砂示例保留适量背景内容，便于观察透明效果。
- 保留原有路由、导航分组及可沿用的章节锚点，确保页面跳转和目录定位稳定。

样板选择理由：Button 覆盖最常见控件和反馈；Input 暴露默认值及类型变化；Select 覆盖选择、虚拟列表和浮层；Card 覆盖容器、磨砂与转场。四个样板逐个完成后，把确定的样式和内容组织方式用于其余组件。

首个实际开发批次建议限定为：**阶段 1 的基线准备 + 公共视觉第一版 + Button 完整试点**。交付浅深主题及窄屏截图、文档差异和验证结果，再依次处理 Input、Select、Card。

### 阶段 3—6：逐组件更新完整内容链路

每个组件都按以下顺序完成：

1. 核对公开 Props、默认值、事件、插槽、实例方法及新旧行为差异。
2. 更新 Markdown 正文和 API 表，补充新能力，重验旧限制及兼容写法。
3. 更新网页预览与参数面板，区分“组件默认值”和“为了演示显式设置的参数”。
4. 同步独立 Vue 示例与动态代码生成，保证复制结果和实际操作一致。
5. 更新登记说明、生成 AI 文档，并同步阅读应用用例。
6. 完成该组件的类型、交互和外观检查，再更新迁移状态。

不按“先改完所有 API，再统一改示例”拆分，以免长期出现页面说明、运行结果和复制代码互相矛盾。

复杂组件重点补充组合验证：Dialog 中的 Form、Select/TreeSelect；Table 中的输入与操作按钮；预览中的菜单与工具栏。库自身的验证记录作为参考，仍要检查文档站真实容器对焦点、层级和滚动的影响。

### 阶段 7：Cursor 单独完成

建议包含五类示例：默认状态识别、状态与过渡、自定义插槽、柔和跟随、全局与局部作用域。

优先在专用演示区体验，提供明确的启停方式；全局演示需要覆盖路由切换和退出清理。说明 Teleport 作用域、触摸与减少动态效果的处理，以及保留原生光标的边界。是否在整个文档站默认启用作为单独的产品选择，不作为新增组件文档的前提。

### 阶段 8：入口和整体收尾

- 首页与组件导航同步实际覆盖范围，补入 Cursor，并沿用第二阶段的视觉标准。
- 快速开始更新安装依赖、样式导入、Vue/Nuxt 接入、主题及新的尺寸说明；内容面向组件使用者，仓库维护说明归入 README。
- 增加从 0.5.3 升级到 0.6.0 的说明，重点列出 Button 节流、Input 模型与清除行为、Form 默认校验及新属性、样式和默认尺寸变化。
- 统一 README、版本清单、`llms.txt`、AI 文件头及覆盖数量。旧版验证记录保留原适用版本，新增本轮验证结论。
- 全部内容验收后再完成对外版本切换，避免中途把尚未更新的页面当作完整新版文档发布。

## 五、验证方式

沿用现有测试体系，按改动范围执行：

| 时机 | 检查 |
| --- | --- |
| 修改导出机制 | `pnpm test:docs-export`、`pnpm typecheck:docs`，检查版本/状态声明及生成一致性 |
| 完成一个组件 | 对应 `tests/browser/<组件>-docs.spec.ts` 与 `tests/ai-browser/<组件>-export.spec.ts`，核对网页和独立示例 |
| 修改公共样式或布局 | 复查样板页、首页/导航、浅深/system 主题及窄视口，检查目录和页面溢出 |
| 一个批次完成 | 执行适用的文档、测试、Nuxt 及 AI 示例类型检查；尚属其他批次的问题记录到差异表 |
| 全站收尾 | 全量 `docs:check`、导出测试、类型检查、`test:docs` 和 `test:ai-examples`；全部通过后确认完成 |

浏览器始终使用无头模式。内置 Chromium 不可用时，通过临时环境变量使用系统 Chrome/Edge，不提交机器专属配置。截图作为临时人工核对材料，不更新像素快照。涉及剪贴板的用例顺序执行。

自动断言通过后仍需查看样式改动的截图。检查结束后清理本轮临时进程及文件。纯文档和样式更新默认不运行完整构建；遇到必须由构建验证的问题时再针对性执行。

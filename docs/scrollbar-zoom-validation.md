# Scrollbar 0.11.2 缩放惯性验证

2026-10-19，组件库发布提交 `83a061d`，npm `latest` 为 `0.11.2`，文档与 AI 导出为 `0.11.2-r1`。

## 原因与修复

现场在生产工作台和 localhost 采样，同一鼠标分别产生 `deltaY≈90.909 / wheelDeltaY=-109` 和 `deltaY=100 / wheelDeltaY=-120`；用户确认前者使用了浏览器缩放。旧识别逻辑将取整后的 109 档位误认为触控板，回退为原生滚动，跳过默认的 400ms 惯性。0.11.0 到 0.11.1 的性能优化没有改动 Scrollbar，该缺陷由缩放条件触发。

0.11.2 根据 Chromium 常见鼠标档位与 CSS 像素的比例补充识别，容纳缩放后的取整误差；实际距离仍使用标准 delta，保持触控板、Ctrl+滚轮、减少动态效果、内部滚动区和边界传递的原有行为。没有给看板增加兼容逻辑，也没有强制接管所有触控板输入。

| 看板真实 Nuxt 与独立测试库 | 正式包下 5 条流程 × 6 组输入，共 30 组通过，无页面异常 |
| 文档网页 | Cursor 9 项、Scrollbar 8 项，共 17 项通过 |

看板流程包括首次正文、版本比较、比较返回正文、工作台返回详情、文档列表返回详情。110% 输入在各流程都被接管，首帧前位移为 0，得到 23 个不同位置，最终正反向位移约 ±76 CSS px，符合 `delta × 100 / 120` 的预期。125% 和普通档位同样通过。

组件库首次并行全量浏览器检查中，一项无关 Input 光标中间帧采样失败；该文件单独复验及全量单 worker 复验均通过。没有更新视觉快照。

## 范围与限制

无头测试重放现场事件参数，并逐帧检查惯性，不等同于穷举真实硬件、浏览器扩展或所有系统滚轮设置。现场采样来自工作台；正文和返回详情由独立测试库的 150 段长文档覆盖，不在生产写入测试正文。此次修复保持 REQ-10 的缓存返回优化，未重复测量完整 REQ-8 图片文档的性能数据。

文档发布使用隔离检出，只提交本次 Scrollbar 和前次 Cursor 的更新；原工作区已有的 Textarea、S1 等未提交内容保留。
